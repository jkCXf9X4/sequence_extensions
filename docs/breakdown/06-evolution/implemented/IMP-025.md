# Flow phase sub-packages and duplication cleanup

Flow modules grouped by lifecycle phase; duplicated helpers extracted; process_pool coverage hardened. Public surface unchanged.

## Pain

- Flat 18-file module: browsing and future extraction (runlog as its own unit, HPC pool) need phase boundaries.
- Six duplicated patterns: timeout-thread block, post-order DAG walk, signature inspection, future predicate, seq/schema stamping, record identity.
- `process_pool.py` at 78% coverage: error paths (dispatch failure, timeout transport, exit cancellation) untested.

## Proposal

- Four phase sub-packages under `flow/`: `_planning/` (dag, document), `_execution/` (node, attempt, run, futures, gather, pickle, process_pool, settle, timeout), `_recording/` (runlog, records, serialize, diff), `_config/` (options, context).
- Extract shared helpers: `_signature_parameters` (`_config/options.py`), `_run_with_timeout` (`_execution/_timeout.py`), `_stamp_record` (`_recording/runlog.py`), `iter_postorder` (graph, public).
- Merge `_identity` into `records.py`; `_is_future` alias removed in favor of public `is_dependency`.
- Close the `process_pool.py` coverage gap to 100%.

## Cost

- Internal move only: no public API change, no log schema change.
- `assets.md` module map updated (`INFO-005`).

## Evidence

- 470 tests pass; overall coverage 94.59%; `process_pool.py` 100%.
- Plan DAG walks kept local: cycle semantics differ from graph's `iter_postorder` (silent once-per-node vs `ValueError`).
