# Restructure flow internals for future development

Internal module layout reorganized around lifecycle phases; public `flow` surface unchanged.

## Pain

- `_plan.py` god-module: DAG plan pass and `flow-plan/1` document interface in one file (690 lines).
- `node.py` mixed decorator, policy, and pickle transport (363 lines).
- `_context.py`: ~30 mechanical ContextVar getter/setter pairs (256 lines).
- Flow imported graph privates `_is_dependency`, `_set_exception_if_pending`.
- `flow_runner` duplicated the `RunOptions` field list and the reserved-`options` binding rule.

## Proposal

- Split by lifecycle phase and transport seam: plan, execute, record, config, runner.
- `_plan.py` to `_planning.py` (plan pass) plus `_plandoc.py` (document interface).
- `node.py` to `_decorator.py` (`@node`, `NodeFunction`) plus `_pickle.py` (pickle transport).
- `_context.py` to one ContextVar holding one frozen state object; accessor names unchanged.
- Graph privates promoted: `is_dependency`, `GraphFuture.set_exception_if_pending`; `GraphPool._submit_node` documented as the pool-extension seam.
- `RunOptions.toml_keys()` single-sources runner config keys; `bind_flow_inputs` single-sources the `options` binding rule.

## Cost

- Pure internal move: no public API change, no log schema change.
- `assets.md` module map updated (`INFO-005`).

## Evidence

- Public surface pinned by `test_flow_public_surface_pinned` (`tests/test_package.py`).
- 464 tests pass; ruff clean; coverage at or above 90.
